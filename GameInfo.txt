PROJECT: Tesla FSD · V2V Fleet Simulation  (browser 3D driving game, Three.js r128 from CDN)
Updated: 2026-10-18

FILES (keep in the same folder, open game.html in a browser)
  game.html  main game: HUD, road, traffic AI, V2V mesh, physics, cameras, audio, interior cockpit
  car.js     PLAYER CAR ONLY (Model Y "Juniper"-style, procedural). Loaded by game.html with <script src="car.js">
  gameInfo.txt  this file

WHAT THE GAME IS
  Endless 6-lane highway. You drive a red Model Y-style car (WASD/arrows, Space handbrake, C camera, M sound,
  hidden Shift = boost) among 36 gold Cybercab AI cars. Tesla-style HUD (gear, mph, speed limit 45, battery,
  "Self-Driving" label), blue FSD path ribbon + lead-car ring/tag, automatic emergency braking (AEB),
  lane-keeping assist, day/night mode, 4 cameras (Follow, Drone, Bumper, Interior with a drawn dash screen).
  NOTE: "Self-Driving" is cosmetic - you steer manually; only AEB + lane-keeping are real.

HOW game.html IS ORGANISED (top to bottom)
  renderer/lights/env reflections -> road texture + barriers + lamp poles -> Cybercab model (makeCar)
  -> PLAYER (built by car.js) + interior cockpit -> FSD ribbon -> traffic AI (IDM car-following, lane
  changes, yield to player = "V2V") -> V2V link lines -> audio (WebAudio, no files) -> input/cameras
  -> day/night -> player physics (stepPlayer) -> camera -> HUD -> main loop (frame)

CONVENTIONS
  Car faces -Z. Units = metres. Lane i centre x = LX(i) = -11.1 + 3.7*(i+0.5), 6 lanes. P = player state
  object (x,z,v,psi,steer,pitch,roll,br,...). Bicycle-model steering, wheelbase WB = 2.9. MPH = 2.23694*m/s.

car.js CONTRACT (what game.html expects - keep this stable when upgrading the car)
  buildPlayerCar({glow}) -> { g, body, wheels, rear, update(P,dt), dims }
  - g: root group (game sets position + heading). body: child group that gets pitch/roll.
  - ALL exterior parts must be children of `body`: game parents the cockpit to body and hides every
    other body child in the Interior camera.
  - update(P,dt) is called every frame: wheel spin + front-wheel steer, body pitch/roll, brake lights.
  - glow(col,w,h,x,y,z,parent) = game's night-glow sprite helper (visible only at night).
  - Origin at ground centre. Size 4.84 x 1.95 x 1.63 m, wheel radius .37, wheelbase 2.86.
  - Interior camera sits at (-0.38, 1.27, 0.15) relative to the car (driver seat) - keep the cabin roomy there.

HOW THE CAR IS BUILT (car.js)
  Body = lofted mesh: 100 cross-sections (rounded super-ellipses) driven by profile curves (yT hood/belt,
  yB underside, nTop edge roundness, planHW width). Paint/black trim is baked as vertex colours.
  Glass house = second loft (gHW width, yR roof line) with black belt trim + B/C pillars.
  Front/rear light bars = tubes following the body contour. Also: aero wheels (turbine blades, steer+spin),
  wheel-arch crescents, door/hood/trunk panel lines, mirrors, brake lights (rear material).
  Easy tweaks: PAINT_HEX/PAINT = colour; the curve control points = shape; WX/WZ/WR = wheels.

DONE SO FAR
  1. Single-file game: driving physics, AI traffic, V2V mesh, HUD, cameras, sound, day/night.
  2. Split project: player car moved to car.js; Cybercab traffic car still inside game.html.
  3. New Model Y-style car (replaces the old extruded-box car).

CHECKED / NOT CHECKED
  Checked: both files parse; car.js geometry math runs with no NaN (headless, stubbed THREE).
  NOT checked: real in-browser look. The car has not been viewed rendered yet - expect to tune proportions,
  light-bar position, wheel look and colours after the first run.

KNOWN ISSUES / TODO IDEAS
  - Help text does not mention Shift boost; V2V "latency" number is random (cosmetic).
  - No real self-driving mode yet (auto steer / lane change / follow traffic).
  - V2V is only a yield rule + visual lines; cars do not really share braking info.
  - Unused in car.js: no interior seats/dash (cockpit lives in game.html); no turn signals, no damage.
  - Possible next splits: traffic.js (Cybercab + AI), hud.js, audio.js, cockpit.js.

UPDATE 2026-10-18 (systems upgrade, game.html; car.js unchanged):
- Battery: iPhone-style battery (shell + nub + rounded fill). Energy model in stepBattery(): wheel power =
  (m*a + drag + rolling)*v. Positive -> drains pack; negative (lifting off W, braking) -> regen charges pack.
  Blue animated fill + bolt while charging, red <20%. Range (mi) = energy left / recent Wh-per-mile.
  Constant DRAIN (=4) speeds energy flow so the change is visible; set DRAIN=1 for realistic. Pack = 75 kWh, starts 78%.
  Battery at 0% = no throttle. Dash screen also shows % and miles.
- Auto Drive (button / key F): lane keeping + adaptive cruise (IDM, limit 45 mph) + overtakes slower traffic when the
  neighbour lane is free. AEB stays active. Driver takes over with S / Space / A / D (W = temporary speed override).
  Label shows "Self-Driving" when on, "FSD Ready" when off. State object: AUTO. Functions: autoDrive(), setAuto().
- AEB fixed: decided BEFORE throttle each frame; cuts throttle, computes required decel (v^2 / 2*(gap-3.5)), brakes up
  to 10.5 m/s2, also a proximity rule under 6 m. Sees cars changing into your lane. (Physically unavoidable if the
  closing speed is too high for the gap, e.g. 90 mph at 60 m.)
- Rain (button / key R): soft streaks around the camera, greyer/darker sky, shorter fog, quiet rain hiss. setRain().
- V2V Mesh toggle (button / key V): hides link lines + cyan node domes on the cars. setV2V().
- Buttons row now: Auto Drive, Rain, V2V Mesh, Day/Night, Camera, Sound. Help text lists F / R / V / Shift.
- Headless-tested (stubbed DOM/THREE): battery drain + regen, AEB scenarios (0 hits except impossible cases),
  auto-drive 120 s with traffic (0 hits, overtakes lanes). NOT checked: real in-browser look (rain, battery CSS).
